# LinkSuite: everything left, in build order

Written 17 November 2026 from the audit of every spec, plan, design doc, ledger and recheck report against main (c58eaf6).
The owner asked for all of it, phase 2 included. This file decides the order. Each wave ships (tests, deploy) before the next starts.

How each wave is run:
- Waves 0 to 3 finish or fix things an approved spec already describes. They go straight to an implementation plan.
- Wave 4 items are new modules. Each gets a short design for the owner to approve, then a plan.

Owner's decisions (17 Nov):
- The order is approved.
- Custom domain is hidden until wave 3 builds it.
- Installable web apps come before native apps.
- Each wave is deployed to production once its tests pass, without asking again.

Ordering rule: honesty and safety first (things sold or promised that don't work), then gaps in approved specs, then known bugs, then platform money, then new modules ordered by how many paying customers they reach.

## Wave 0: honesty and launch safety (about 1 to 2 days)

1. OrderLink Pro "Custom domain": hide it from the Pro feature list until wave 3 builds it, so nobody pays for something missing.
2. Privacy policy and terms pages, shared across all 8 sites and linked in the footer and at signup.
3. Private storage bucket setting for verification documents (property ID documents, school and clinic private files). Second bucket config; private files never get public URLs.
4. Nightly database backup on the VPS: `pg_dump` to `/root/linksuite-backups`, keeping 14 days, as a script in `deploy/` plus a cron line in the handoff.
5. Error tracking: a server-side error log endpoint plus API exception capture, with optional Sentry when a DSN is set. No account needed to ship.
6. Tidy: README status table (CareLink final review done) and the deploy handoff checklist and date.

## Wave 2: known bugs (about 1 week)

The roughly 40 small confirmed items from the audit, done one product at a time, each with a failing test first. Lists:
- `.superpowers/recheck/*.md`: items marked left alone in the fixes files;
- final-review minors in `.superpowers/sdd/*`;
- `docs/superpowers/carelink-rulings-and-minors.md` (deferred minors).

From the Wave 0 review, added here:
- InvoiceLink expense receipts are stored under a public key (`{tenant}/expenses/…`). Move them under `private/`, read them through the API, and migrate the existing files.
- An API error that comes back after being marked fixed reopens without an email. It should email like a new one.
- Redact secrets from stored stack traces (URLs with keys, tokens).

From the Wave 1 review, added here:
- Plan reminders: an open-ended comp next to a paid plan suppresses the paid plan's reminder. The price check uses the plan's current price, not the price paid.
- Parent email change: make the attempt count atomic, and turn a race on the same address into a 409, not a 500.
- Boost mismatch alert: a webhook and the return page arriving together can both send it. Use a marker or a conditional update.
- Patients' phone numbers now appear in WhatsApp links for every role that sees appointments or the queue (cashier included). Confirm that is wanted, or limit it to the desk.
- Portal reschedule: re-check the doctor under the lock.
- Terms must stay inside the session's dates (not checked yet).
- PDFs print the signer's current signature, also for staff who have since left. Freeze the signature at signing.
- No download route yet for the files of corrected (superseded) test results.
